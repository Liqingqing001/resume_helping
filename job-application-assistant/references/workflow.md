# 字段与保存工作流

1. 核对账号、招聘渠道、当前默认简历/申请草稿以及用户本次授权范围。先备份需要修改的业务字段，私密字段只在页面内比对，返回是否一致。
2. 按“网站标签→资料键→来源→是否确定→控件”映射，区分文本、下拉、日期、附件和重复经历。学历不等于学位；籍贯不等于现住址；未来可到岗日期不等于既往任职起始日期。
3. 逐条对应公司与项目。解析PDF后核对姓名、学历、专业、任职职位、日期、描述截断、乱码、重复条目及链接。不要让旧的“其他”等占位值覆盖确认资料。
4. 受控input/textarea需触发实际input/change，之后检查状态回显。下拉按当前实际选项标签选择，不猜编码；如需使用DOM关联的组件onChange，仅使用观察到的选项。日期控件按实际支持精度处理，“至今”含义不能跨站复制内部值。
5. 新增条目由页面生成；重排保留原条目ID。用户删除的经历同步清除。检查正文与文件名中的旧岗位限制、自我评价中的旧文案、证书和附件版本。
6. 走正常保存及页面校验，等待明确结果。超时先查状态，不能重复提交。刷新后比对持久值，部分网站预览不显示职位等字段时，可核对编辑页回显或DOM关联的最新业务数据；不直接向未知API构造写请求。
7. 未知必填项集中询问；其他资料先填好。现有历史投递不保证随默认简历更新，个人中心保存不等于新投递。

## 提速与恢复

优先已验证深链接、区块标签与稳定属性；别每次从首页全量探索。后台页面动画或短定时器可能被延迟，先使用同一连接的`foreground:true`。字节特定简历动画可用严格限定URL与组件的恢复脚本。网页隐藏不一律代表同一问题，不能跳过登录、校验或安全拦截。

遇到网站结构变化只重新观察失败的控件。工作流记录标明入口已观察、填写已验证或保存回读已验证，避免把计划写成成果。真实资料与运行会话ID不提交到仓库。
