# 求职助手

先读取用户工作区的`profile.local.json`及其指向的个人资料、当前简历、展示规则和已有同步记录。首次配置缺失时只询问必要路径；配置目录为空时先从用户提供的已确认材料建立资料，不把空目录或占位路径当作简历已就绪；不要索取已经加密保存的身份证明文，也不要使用技能作者的资料。默认Windows PowerShell，Python用`py`。

填写前阅读[工作流](references/workflow.md)和目标[平台记录](references/platforms.md)。更新简历默认涵盖附件与对应在线字段，用户明确仅附件时除外。对旧网站、简历原稿和新说明的冲突，以用户最新确认优先。

浏览器使用`scripts/cdp-inspect.cjs`的一条常驻连接。先读[连接复用与恢复](references/browser-session.md)，核对可继续访问的已有会话，再决定是否启动客户端；禁止每站重连或自动轮换地址。不要批量导出私密页面、Cookie或凭据。

若配置了Overleaf项目且用户要求在线维护，读[在线编辑与PDF交付](references/overleaf.md)，在该项目备份、编辑、编译并核对下载PDF；本地打开的源文件原地维护。无Overleaf要求的用户不强制配置账号。PDF必须检查中文提取、字体、页面布局和链接，不仅检查编译返回成功。

求职意向、证书、经历数量、日期精度、文件名和到岗承诺均服从用户自己的规则。集团背景不替代真实雇主；内容与指标需有来源。

填写和保存属于已授权的简历更新范围；新岗位投递、发消息或改变其他账号设置需有对应用户授权。登录/验证码等确实需要用户参与的环节说明具体停点，继续完成独立工作。不要为了速度绕过校验或把未验证网站标成成功。

保存后刷新核验，记录字段差异、PDF版本、时间、站点结果及待确认项。平台技术经验写通用记录，个人值与回执只写用户私有目录。新增平台先复用字段映射流程，再补充实际观察的定位与成功判据。
